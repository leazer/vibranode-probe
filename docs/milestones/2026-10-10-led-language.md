# 2026-10-10 灯语重设计（白=链路层，红=警告/故障分级）

## 背景

USB CDC 改造收官（round-20，200 MHz 标准工作点）后重新梳理灯语。旧 M6 词汇
（灭/蓝常亮/绿常亮/紫1 Hz/黄2 Hz/红5 Hz）有两个盲区：① 上电未连 USB 与
未绑会话同为全灭，分不清"没插线"和"没握手"；② 黄/红两级故障颜色相近、
闪烁率只差一档，现场不易读。

## 新词汇（用户定稿，2026-10-10 冻结）

| 状态 | 现象 | 说明 |
| --- | --- | --- |
| 6 无 USB 主机 | 白闪 1 Hz（500/500 ms） | 固件本地状态，**不上线**（帧只在 USB 活着时才会发） |
| 0 已枚举未绑会话 | 白常亮 | 取代旧"全灭" |
| 1 待机 | 蓝闪 1 Hz（100/900 ms） | 短亮长灭，省电且醒目 |
| 2 测量健康 | 绿 1 Hz 双脉冲（100/100/100/700 ms） | "心跳"感 |
| 3 校准采集中 | 紫 5 Hz（100/100 ms） | 提速以区别于旧紫 1 Hz |
| 4 测量中警告 | 红 5 Hz（100/100 ms） | 原黄 2 Hz 取消，黄色停用 |
| 5 测量中主通道故障 | 红常亮 | 原红 5 Hz 改常亮，闪烁→常亮=更严重 |

引导期 EOPB0 守卫灯语不变（紫 4 闪/紫 4 Hz 成功/红 8 Hz 失败）。

## 实现

- `probe_usb_connected()`（probe_usb.c/.h）：`usb_core.conn_state ==
  USB_CONN_STATE_CONFIGURED`，即主机 SET_CONFIGURATION 完成。挂起（主机睡眠、
  拔线后 SOF 停止触发 suspend IRQ）与总线复位都读作"无主机"，重插重新枚举后
  自动恢复——拔线检测无需新增硬件。
- `probe_led.c` 重写为相位表引擎：每状态一组 (通道掩码, 相长 µs) 循环步进，
  支持非对称占空与双脉冲（旧引擎只有 50% 单频）。切态从首个亮相位开始，
  翻转时刻沿用 catch-up 累积语义。
- `probe_proto_poll`：`probe_led_update(probe_usb_connected() ? work_state(bits)
  : 6)`。**线上协议零改动**：STATUS_NOTIFY p[3] / GET_STATUS p[4] 仍输出
  work_state 0-5，状态 6 只存在于板上灯。
- 模式 3 `l` 键巡检 12→14 秒（每态 2 秒，覆盖新增状态 6）。

## 顺手修复

- EOPB0 校验失败灯：`76f48d1` 的 `early_led()` 重构把红通道写成了 `LED_G`
  引脚（会闪绿）。恢复原 `99de6c9` 行为驱动 `LED_R`（`342e925`）。
- 设计文档 pin 表笔误修正（根仓 `6aa6611`，当时按原理图记 R=PB5、G=PB3、
  B=PB4）。

## 实板复核（2026-10-11，M2 `l` 键逐管脚测量）

- **根因：LED 焊反 180°**——同一颗器件反焊同时解释了"R/B 对调"（引脚镜像）
  与"绿管芯不亮"（顶到阳极位反偏）。返修复焊后板子与原理图一致，宏回正为
  **R=PB5、G=PB3、B=PB4**（焊反期间曾临时换为 R=PB4/B=PB5，`a8f3ad3`，
  返修后回退）。后续核对以**实测**为准。
- 返修后实板微调三处图案（板上观感定稿）：
  - 状态 0（已枚举未绑会话）：白常亮 → **蓝常亮**（白只留给"无主机"）；
  - 状态 1（待机）：1 Hz 100/900 → **2 秒心跳 100/1900**；
  - 状态 2（测量）：双脉冲 100/100/100/700 → **100/50/100/750**（间隙收紧）。
- SWD-only 调试（不开 SWO）不占用 PB3；wk_config 的 SWJTAG_GMUX_010 重映射
  已释放 PB3/PB4/PA15，实测 PB3 随绿相位正常拉低证实通路完好。

## 启动红闪溯源与定版（2026-10-12）

- 现象：Slow / 4k+8k 每次 START 后先红 5 Hz 闪 ~1 s 再转绿双脉冲，ODR 无关。
- 机制：START 配置路径复位时间轴估计器（"New configuration: timeline
  restarts"），ICM 需 8 次 ≥100 ms 观测跨度才 `aligned≥8`（首读等 100 ms +
  ~800 ms 收敛），期间 fault bit7（`measuring && !time_valid`）→ work_state 4
  红 5 Hz；ADXL ~100 ms 即收敛、被 ICM 淹没。窗口内数据无损（4k+8k 终验
  双流 100% 即含此窗口）。
- 溯源（回应"是否 16k 轮改出"）：bit7 由 `de02a62`（09-07，publish
  estimated timeline）引入，早于 16k 攻坚一个多月。对验收固件
  `cf5b134`..`6d741a7` 全量 diff 审计：16k 轮九笔提交未触碰该路径——
  `time_valid` 唯一改动是 `&& !time_dirty`（启动时 time_dirty 恒 0，中性），
  work_state/fault_bits/probe_led.c 未动，8k 读节流减半后又恢复原值净变化零。
- 此前"看不到红灯"的原因：LED 焊反 180° 期间固件的红图案物理上点亮蓝管芯
  （绿不亮），能正确显示红色的板子 10-11 凌晨返修后才存在；返修距 16k 攻坚
  仅十几个小时，验收时注意力在 TAB5 日志上。
- **用户拍板（2026-10-12）：保持现状不改，定版**——红闪作为"时间线未锁定"
  的诚实告警保留，不作绿显。
