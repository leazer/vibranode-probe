# M2 组件分层审查与整改

## 审查发现及处理

1. `probe_validation.c` 同时拥有两种芯片的寄存器表、SPI 编码和解码，芯片知识与测试编排混在一起。将这些无状态操作分别归入 ADXL357 和 ICM42688 组件；检查状态、错误计数与日志仍属于诊断应用。
2. SPI CS、RS485 DIR 和 LED 调用写死物理引脚，生成初始化也假设所有 LED 同端口。全部改用 wk_config 的已有信号宏。生成器内部 EXINT 路由配置仍由 Workbench 维护。
3. 诊断读取依赖固定 16 字节临时缓冲，没有入口长度检查。增加边界检查；临时缓冲仍由 SPI 层复制后异步使用，不延长栈对象生命周期。
4. 正式与诊断配置边界不清。组件接口显式命名 diagnostic_settings，并记录生产采集不得调用诊断轮询；没有把本轮重构声称为 FIFO 驱动完成。

## 已有硬件反馈

用户提供的 M2 日志显示两路 ID/配置通过、诊断无错误，RGB 正常，A/B 端能测到 5 Mbps 发送信号。该反馈属于重构前 M2；尚不能证明双向持续通信、完整采集或本次重构后硬件验收。

## 本次验证

- 重构前与重构后诊断仿真均通过。
- 新增独立的 M2 寄存器写入黄金序列，检查 ADXL 六步、ICM 八步及重试后序列一致。
- 验证身份失败、独立超时、重试、符号解码与短缓冲拒绝；SPI DMA 回归通过。
- Keil 全量编译 0 错误、0 警告；Code 15492、RO 1364、RW 16、ZI 5232 字节。相比 M2 Code 增加 292 字节，RW/ZI 不变。
