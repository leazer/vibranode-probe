# M4 RS-485 链路与协议层

日期：2026-09-07。开发分支 `codex/probe-foundation`，前一里程碑 `90bd468`。依据：已冻结的 [RS-485 协议编码表](../../../../../docs/superpowers/specs/2026-09-07-vibranode-rs485-protocol-design.md)（执行中发现并勘误 3 处数值笔误，见下）。

## 本次实现

- `probe_frame`：CRC-32C（位循环实现，自检向量 `123456789`→`E3069283`）、帧构造、增量解析器（帧头扫描/15 字节定长前缀/载荷连续性 50 ms/重同步）。结构合法帧全部交付，类型与载荷上限校验按角色归协议层。
- `probe_uart`：USART1 半双工链路。RX 为 DMA1 CH5 硬件循环环（1024 B，套圈即计错并整环作废）；TX 为 CH6 单次传输 + USART TDC 收尾后拉低 DIR（沿用 M2 实测时序）；待机改速率并重置接收环。
- `probe_proto`：会话绑定/幂等缓存（存完整应答，重试可恢复 STOP 边界）/配置映射与校验/START-STOP 与采集联动/FETCH 窗口（预算、20 ms 截止、双流轮转、TIME_INFO 每段+每秒、STATUS 500 ms 探头级节拍、FETCH_DONE 必发）/SET_LINK 100 ms 静默切速与 3 s 无帧回退。CALIBRATE/SAVE_CAL 按约定应答 NOT_IMPLEMENTED。
- `probe_acquisition` 增加最后交付样本边界（`last_sequence/last_read_us`）与队列积压字段，供 STOP 边界与 GET_STATUS 使用。
- `main.c` 三模式：0=生产（采集+协议）、1=M2 诊断、2=M3 采集消费。
- `tests/pc_host.py`：PC 侧 TAB5 角色脚本（发现、5 Mbps 协商、测量会话、FETCH 排空、CRC/丢帧注入、`--selftest` 黄金向量自检）。

## 规范勘误（随实现核对冻结文档发现，载荷字段本身未变）

1. SET_LINK 应答上限 8→9；FETCH 请求上限 5→8；GET_STATUS 应答上限 96→115（每流记录 42 字节，非 36）；SET_CONFIG 请求上限 13→17、应答 16→14。
2. 补充 TIME_INFO（0x12）载荷表（原表缺载荷定义）与帧总长公式 15+载荷+4。
