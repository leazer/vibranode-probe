# 首轮单板 RTT 实板反馈与修复

用户回传日志包含旧M2、M3和新版BOARD多段；本结论仅分析行3454起的新版单板段（929条BOARD日志）。原附件SHA256：`d64f14b0dc2f50c5f3a6ad74321075f5d3f481a1a5213811cd1f455ee0e32ab0`。日志覆盖上电至约246秒，中间有明显输出缺口及连接中断，不是完整连续记录，也未达到30分钟验收。

## 实板观察

- 所有已输出的BOARD `spi/ovr/fmt/qdrop/attdrop/fault` 均为0，默认档首末样本计数差对应ADXL约4054.04 SPS、ICM约8038.43 SPS；后段32k档约32154.27 SPS。计数与消费数相等，未观察到队列丢失。
- ADXL默认档 `time_valid=1`，周期约16166000 Q16.16（约246.67 µs）。ICM高速档IRQ计数保持不变、样本持续增加，但 `time_valid/tick_valid` 不收敛。200 SPS短暂出现有效，记录不足以判断长期表现。
- 默认档AGM `valid=1`、processed持续增长，切到非8k档关闭，回到8k重新运行。仅证明本轮输出存在，不代表振动下姿态精度、轴向或yaw漂移已验收。
- `g` 在约115.140秒启动，约116.135秒通过；候选陀螺零偏为−0.224/−0.330/−0.098 dps，flags=2、dirty=1。运行中`v`正确拒绝。未见 `x/w/SAVE PASS`，因此未验证Flash写入/掉电/重载；也未执行ADXL六面流程。
- 最大观测单轮耗时：采集117 µs，姿态578 µs，总轮询991 µs。所有88条栈报告均为0/2048，不能用本日志验收栈预算。

## 根因和修复

1. **栈水位失真**：默认链接的STACK仍被ARM C运行库作为ZI清零。首版在Reset_Handler中填充，执行到`__main`后就被清掉。用实际AXF执行Reset→CRT→main已复现；首版测试停在SystemInit之前，漏测CRT，这是测试覆盖缺陷。
   - 改为main第一步调用leaf汇编`probe_stack_init`，在CRT之后、板级初始化之前，只填充栈底到当前MSP，保留活动栈帧。水位覆盖之后执行的板级初始化、应用、中断，不覆盖之前的CRT/SystemInit。
   - 不因旧日志0值盲目扩大栈；仍保留2 KiB，必须用新镜像确认真实余量。旧0值不排除其他实际栈风险。
2. **ICM时钟映射依赖停止更新的水位IRQ**：轮询及时排空FIFO后，水位条件不再成立；样本仍正常产生，但估计器拿不到新IRQ锚点。
   - ICM改用FIFO_COUNT请求/完成时刻中点，减去半周期样本年龄；超过512 B时减去仍留在FIFO尾部的样本时长，使锚点对应本批实际末样本。
   - ICM周期和tick比例采用至少100 ms观测跨度，连续8次一致才有效。ADXL保留DRDY与10 ms跨度。此观测包含SPI请求/主循环收割延迟及采样相位误差，不具有精确IRQ捕获的含义，绝对精度仍需外部时基验证。
3. **批次时间未随序号投影**：旧公式把保留的anchor_us当作每批新末样本时刻，估计窗口内批首时间会重复。现在按当前first_sequence相对anchor_seq投影。
4. **TIME_INFO仍用旧IRQ时间**：改为与first_sensor_tick/first_sequence对应的first_sample_us；线上字段布局不变。真实485/TAB5验证继续后移。

## 软件验证

- 现场回归模型由独立124 µs时钟产生ICM样本，FIFO低于水位、没有ICM IRQ；修复前不能收敛，修复后time/tick均有效、估计周期符合独立时钟，并验证相邻批首时间推进。
- 追加200/16000/32000 SPS无IRQ场景，均通过。仿真未涵盖所有寄存器采样相位和>512 B积压时的绝对误差分布，需结合实板数据继续评估。
- 协议测试无ICM IRQ时TIME_INFO时间推进且与对应STREAM批首时刻相等；修复前失败，修复后通过。
- 实际AXF验证执行完整CRT（仅跳过硬件SystemInit），停于板级时钟初始化入口，检查水位未被清除、检测人工覆盖，并检查链接段未侵入Flash标定区。
- 11个组件回归和时间回绕测试通过；四模式完整Rebuild均0错误0警告。只读审查发现的TIME_INFO关联问题已修复。
